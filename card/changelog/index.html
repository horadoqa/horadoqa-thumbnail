Guia fundamental

Changelog
que comunica.

Um changelog transforma alterações técnicas em uma história clara sobre a evolução de um produto. Mais do que listar commits, ele registra o que mudou, por que mudou e como isso impacta quem usa ou mantém o sistema.

CONCEITO / 01

O que é um changelog?

É um registro organizado das mudanças feitas em um produto, sistema ou projeto ao longo do tempo. Pode incluir novas funcionalidades, correções de bugs, melhorias, mudanças técnicas e alterações que exigem atenção dos usuários.

NÃO CONFUNDA

Changelog ≠ histórico de commits

O changelog é escrito para ser compreendido por pessoas. Um histórico de commits registra o trabalho realizado no código. Um bom changelog traduz mudanças técnicas em informação útil.

Por que importa?

VALUE / 003
01 / TRANSPARÊNCIA

Mostra a evolução

Permite acompanhar o que foi alterado entre versões e entender como o produto está evoluindo.

02 / QA

Apoia os testes

Ajuda QA a identificar o que mudou, quais áreas podem ter sido afetadas e onde concentrar a validação.

03 / USUÁRIO

Melhora a comunicação

Dá contexto para usuários, suporte, produto e desenvolvimento entenderem o impacto real de cada versão.

Como criar?

PROCESS / 004
01

Reúna as mudanças

Liste as alterações relevantes da versão. Consulte issues, pull requests, tarefas e registros de desenvolvimento.

02

Classifique

Separe as mudanças por tipo: nova funcionalidade, melhoria, correção, alteração técnica ou mudança que exige ação.

03

Escreva para pessoas

Evite linguagem excessivamente técnica. Explique o resultado da mudança e, quando necessário, seu impacto para o usuário.

04

Revise antes de publicar

Confirme se as informações estão corretas, completas e consistentes com a versão realmente entregue.

Tipos de mudanças

CATEGORIES / 005
ADDED

Adicionado novos recursos

Use quando uma nova funcionalidade ou recurso for introduzido no produto.

CHANGED

Modificado alterações

Use para alterações realizadas em recursos que já existiam, sem necessariamente removê-los.

DEPRECATED

Obsoleto em transição

Indica recursos que continuam disponíveis, mas estão marcados para remoção em versões futuras.

REMOVED

Removido retirado

Use quando um recurso, funcionalidade ou comportamento foi removido nesta versão.

FIXED

Corrigido bug fix

Use para registrar correções de bugs, defeitos ou comportamentos incorretos encontrados no sistema.

SECURITY

Segurança vulnerabilidades

Use quando a versão contém uma correção ou melhoria relacionada à segurança ou a uma vulnerabilidade.

Um bom exemplo

CHANGELOG / V2.4.0
VERSION / 2.4.0

Melhorias de experiência

07 OUT 2026
ADDED

Filtro por status

Adicionado filtro por status na tela de chamados para facilitar a localização de tickets em aberto.

CHANGED

Nova experiência de login

Modificado o fluxo de login para simplificar a autenticação e reduzir etapas desnecessárias.

FIXED

Correção na busca

Corrigido problema que fazia alguns resultados não aparecerem quando a busca utilizava caracteres especiais.

DEPRECATED

API v1

A versão 1 da API foi marcada como obsoleta e será removida em uma próxima versão.

REMOVED

Relatório legado

Removido o relatório antigo que foi substituído pela nova versão disponível no painel administrativo.

SECURITY

Correção de segurança

Corrigida uma vulnerabilidade que poderia permitir acesso indevido a determinados recursos da aplicação.

O que evitar?

QUALITY / 006

Escreva assim

  • “Adicionado filtro por status na lista de chamados.”
  • “Corrigido erro que impedia o login em determinados casos.”
  • “Marcada a API v1 como obsoleta para remoção futura.”
  • “Corrigida vulnerabilidade no controle de acesso.”

Evite assim

  • “Fix bug.”
  • “Alterações diversas.”
  • “Refatoração geral.”
  • “Commit 8f42c1a — ajustes no backend.”
