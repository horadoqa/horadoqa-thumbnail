Git e padronização de mensagens

Commit Semântico —
Um histórico que comunica.

O Commit Semântico é uma convenção para escrever mensagens de commit de forma padronizada, clara e descritiva. Baseado no Conventional Commits, ajuda a compreender alterações no código, facilita revisões e permite automatizar processos como a geração de versões e changelogs.

CONCEITO / 01 Estrutura

Como funciona?

Uma mensagem de commit semântico segue uma estrutura padronizada que identifica o tipo da alteração, o escopo opcional e uma descrição objetiva. 

tipo(escopo): descrição da alteração

Tipo: natureza da mudança. Escopo: módulo afetado. Descrição: resumo da alteração. 

feat(auth): adiciona autenticação com Google
CONCEITO / 02 Classificação

Principais tipos de commit

Cada tipo comunica a intenção da mudança e ajuda a identificar rapidamente o propósito de uma alteração.

  • feat: nova funcionalidade.
  • fix: correção de defeito.
  • docs: documentação.
  • style: formatação sem alterar a lógica.
  • refactor: reorganização interna do código.
  • test: criação ou alteração de testes.
  • perf: melhoria de desempenho.
  • build: ferramentas e dependências de build.
  • ci: integração contínua.
  • chore: manutenção geral.
  • revert: reversão de um commit.
CONCEITO / 03 Aplicação

Exemplos práticos

O tipo e o escopo ajudam a compreender a mudança sem precisar analisar imediatamente todo o código. 

feat(usuario): adiciona cadastro de usuários

Implementa uma nova funcionalidade.

fix(login): corrige validação de senha

Corrige um problema existente.

docs(readme): atualiza instruções de instalação

Atualiza a documentação do projeto.

refactor(api): simplifica tratamento de erros

Melhora a estrutura interna sem alterar o comportamento externo.

test(pagamento): adiciona testes de reembolso

Adiciona verificações para validar o comportamento do sistema.

CONCEITO / 04 Detalhamento

Descrição detalhada

Quando a primeira linha não é suficiente, a mensagem pode incluir um corpo explicativo e um rodapé com referências a tarefas ou alterações incompatíveis. 

feat(pagamento): adiciona suporte a Pix

Implementa a criação de cobranças via Pix
e permite consultar o status do pagamento.

Closes #123

A primeira linha resume a mudança, o corpo apresenta detalhes e o rodapé referencia uma issue relacionada.

Uma mudança incompatível pode ser indicada com ! após o tipo ou com BREAKING CHANGE: no rodapé. 

feat(api)!: altera formato da resposta de usuários
CONCEITO / 05 Versionamento

Commit semântico e SemVer

Os commits podem apoiar a automação do versionamento semântico, conhecido como Semantic Versioning (SemVer). 

MAJOR.MINOR.PATCH
  • MAJOR:

    mudanças incompatíveis.

  • MINOR:

    novas funcionalidades compatíveis.

  • PATCH:

    correções compatíveis.

A relação convencional é fix → PATCH, feat → MINOR e BREAKING CHANGE → MAJOR. As regras efetivas dependem das ferramentas e configurações do projeto.

CONCEITO / 06 Consistência

Boas práticas

Mensagens consistentes tornam o histórico mais útil para desenvolvedores, revisores e ferramentas de automação.

  • Utilize verbos que descrevam claramente a alteração.

  • Evite mensagens genéricas, como "ajustes" ou "alterações".

  • Prefira commits pequenos e com mudanças relacionadas.

  • Utilize o escopo quando ele ajudar a identificar a área afetada.

  • Mantenha um padrão consistente em toda a equipe.

  • Descreva o que mudou, não apenas que o código foi modificado.

CONCEITO / 07 Prática

Como criar um commit semântico

O processo é o mesmo de um commit comum. A diferença está no padrão adotado para escrever a mensagem. 

git add .
git commit -m "feat(produto): adiciona filtro por categoria"

Para corrigir um problema:

git commit -m "fix(carrinho): corrige cálculo do frete"

Para atualizar a documentação:

git commit -m "docs(api): documenta endpoint de produtos"

Fluxo de um commit semântico

ETAPA / 01

Identificar

Compreender a natureza da mudança e selecionar o tipo de commit adequado, como feat, fix ou docs.

ETAPA / 02

Descrever

Definir o escopo quando necessário e escrever uma mensagem clara, objetiva e consistente.

ETAPA / 03

Registrar e automatizar

Criar o commit, manter o histórico organizado e permitir automações conforme as regras do projeto.

Clareza e consistência no Git

Um commit explica. Um histórico conecta. Um padrão automatiza.

O Commit Semântico transforma mensagens de alterações em informações estruturadas. Com uma convenção consistente, fica mais fácil revisar mudanças, entender decisões técnicas, gerar changelogs e integrar o histórico do Git aos processos de versionamento.

pergunte o que mudou, onde mudou e por que mudou.
