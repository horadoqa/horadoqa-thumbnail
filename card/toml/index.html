Formatos de dados

JSON vs.
TOML

Dois formatos de texto usados para representar informações, mas com propostas diferentes. Entenda o significado de cada um, como funcionam e quando faz sentido utilizar JSON ou TOML.

FORMATO / 01 DATA

JSON .json

JavaScript Object Notation — ou "Notação de Objetos JavaScript". É um formato leve para representar e transportar dados estruturados. Apesar do nome, pode ser utilizado por praticamente qualquer linguagem de programação.

{ "nome": "Ana", "idade": 28, "ativo": true }
FORMATO / 02 CONFIG

TOML .toml

Tom's Obvious, Minimal Language — "Linguagem Óbvia e Minimalista do Tom". Foi projetado para ser simples de ler e escrever, sendo especialmente útil para arquivos de configuração.

nome = "Ana" idade = 28 ativo = true
CONCEITO / 03 STRUCTURE

Estrutura syntax

No JSON, objetos são delimitados por chaves e propriedades utilizam dois-pontos e vírgulas. No TOML, configurações simples podem ser escritas diretamente como pares chave = valor.

JSON { "porta": 8080 } TOML porta = 8080
CONCEITO / 04 PURPOSE

Finalidade use case

JSON é muito comum na comunicação entre sistemas e APIs. TOML é especialmente interessante para configurações mantidas manualmente, onde a legibilidade é uma prioridade.

JSON → APIs / dados / integração TOML → Configuração / ferramentas / projetos

Quando usar JSON?

Prefira JSON quando o objetivo principal for representar dados estruturados ou realizar a comunicação entre aplicações. Ele é extremamente comum em APIs, aplicações web e sistemas distribuídos.

Quando usar TOML?

Prefira TOML quando estiver criando um arquivo de configuração que será lido e editado frequentemente por pessoas. Sua sintaxe foi pensada para ser clara e fácil de compreender.

QA-REF / RESUMO

A diferença em uma frase.

JSON é muito utilizado para representar e transportar dados entre sistemas, enquanto o TOML é especialmente voltado para arquivos de configuração simples, legíveis e fáceis de editar.
