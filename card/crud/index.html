Fundamentos de API

Entendendo
o CRUD

Quatro operações fundamentais para manipular dados em uma aplicação. Criar, consultar, atualizar e excluir são ações presentes em praticamente todo sistema — e entender como funcionam é essencial para quem testa APIs.

OPERAÇÃO / 01 CREATE

Criar POST

É a operação responsável por inserir um novo registro no sistema. Em uma API REST, normalmente usamos o método POST para enviar os dados que serão cadastrados.

OPERAÇÃO / 02 READ

Consultar GET

Permite recuperar informações já armazenadas. O método GET pode retornar um único registro, uma lista de dados ou resultados filtrados, dependendo do endpoint.

OPERAÇÃO / 03 UPDATE

Atualizar PUT / PATCH

Serve para modificar um registro existente. Em APIs REST, PUT costuma representar a substituição do recurso, enquanto PATCH permite alterações parciais, conforme o contrato da API.

OPERAÇÃO / 04 DELETE

Excluir DELETE

Responsável por remover um registro ou solicitar sua exclusão lógica. O método DELETE expressa essa intenção, mas o resultado depende das regras e da implementação do sistema.

Aplicação prática / 01

CRUD na prática com uma API REST

Imagine uma loja virtual que precisa administrar seus produtos. Cada operação CRUD corresponde a uma ação sobre os dados. Em um projeto de testes, você pode validar essas operações usando o ServeRest, uma API de demonstração voltada ao aprendizado de testes de serviços web.

Recurso: Produtos

REST API
POST

Cadastrar um produto

Enviar os dados de um novo produto para a API e verificar se o cadastro foi realizado conforme o contrato.

POST /produtos
GET

Consultar produtos

Recuperar os produtos cadastrados e validar os campos retornados, a paginação e os filtros disponíveis.

GET /produtos
PUT

Atualizar um produto

Alterar os dados de um produto identificado por seu ID e confirmar se as mudanças foram persistidas.

PUT /produtos/{id}
DELETE

Excluir um produto

Solicitar a exclusão de um produto e verificar se a API responde conforme esperado e se o registro deixa de estar disponível, de acordo com as regras do serviço.

DELETE /produtos/{id}
Aplicação prática / 02

Como isso aparece nos testes?

Uma requisição HTTP contém informações que precisam ser enviadas corretamente. Veja um exemplo de criação e outro de consulta. Os caminhos abaixo são ilustrativos: confirme os endpoints, os campos obrigatórios e as regras na documentação da API utilizada.

01. Criando um registro

O teste envia um corpo JSON com os dados do produto. Depois, verifica o código HTTP, a mensagem retornada e a existência do registro criado. 

// POST /produtos
{
  "nome": "Teclado QA",
  "preco": 150,
  "descricao": "Teclado mecânico",
  "quantidade": 10
}

02. Consultando registros

Após o cadastro, o teste consulta a coleção de produtos ou o recurso específico, conforme os endpoints disponíveis. A resposta deve respeitar o contrato definido. 

// GET /produtos
{
  "quantidade": 1,
  "produtos": [
    {
      "nome": "Teclado QA",
      "preco": 150
    }
  ]
}
Aplicação prática / 03

O olhar de quem testa

Testar CRUD não significa apenas verificar se a requisição retorna sucesso. É importante validar os dados, as regras de negócio e os cenários em que a operação não deve ser permitida.

Checklist de testes CRUD

Para cada operação, valide tanto o caminho feliz quanto os cenários negativos e os limites definidos pelo sistema.

  • Cadastro com dados válidos.
  • Campos obrigatórios ausentes ou inválidos.
  • Consulta de registros existentes.
  • Consulta de ID inexistente.
  • Atualização com dados válidos.
  • Atualização de registro inexistente.
  • Exclusão de registro existente.
  • Exclusão de registro inexistente.
  • Validação do status e do corpo HTTP.
  • Persistência e consistência dos dados.
Quality notes / 004

Guarde esta diferença

CRUD descreve as quatro operações fundamentais sobre dados. HTTP oferece métodos que frequentemente são usados para expressar essas operações em APIs REST. A relação é comum, mas não é uma equivalência rígida: o comportamento real depende do contrato de cada endpoint.
