Arquitetura de aplicações

Front-end,
Back-end & Banco

Um sistema web normalmente é dividido em diferentes camadas. O front-end apresenta a aplicação para o usuário, o back-end concentra regras e processa as requisições, enquanto o banco de dados armazena as informações. Em um e-commerce, essas partes trabalham juntas para transformar uma ação na tela em uma operação real no sistema.

CAMADA / 01 UI

Front-end interface do usuário

É a parte da aplicação que o usuário visualiza e utiliza. Em um e-commerce, pode apresentar produtos, carrinho, formulários, login, pedidos e mensagens de erro. Ele conversa com o back-end para obter e enviar dados.

CAMADA / 02 API

Back-end regras e processamento

É a camada responsável pelo processamento das requisições e regras de negócio. Uma API pode receber uma requisição para consultar produtos, cadastrar usuários, autenticar clientes ou registrar pedidos.

CAMADA / 03 DATA

Banco de dados persistência

É onde os dados da aplicação são armazenados e consultados. Em um e-commerce, podem existir informações de usuários, produtos, carrinhos, pedidos e outros registros necessários para o funcionamento do sistema.

Exemplo / Jornada de compra

O que acontece quando o usuário compra um produto?

A mesma ação pode atravessar todas as camadas da aplicação. O usuário vê um produto no front-end, a aplicação solicita informações ao back-end, o back-end consulta o banco e, depois, devolve o resultado para a interface.

01 / FRONT-END

Usuário

O usuário acessa a loja e clica em "Adicionar ao carrinho".

02 / API

Requisição

O front-end envia uma requisição para a API informando o produto e a operação desejada.

03 / DATABASE

Persistência

O back-end consulta ou atualiza os dados necessários no banco de dados.

04 / RESPONSE

Resultado

A API devolve uma resposta e o front-end atualiza a tela para o usuário.

FRONT-END

O que o usuário vê

A interface apresenta produtos, preços, imagens, carrinho, login e informações dos pedidos. Ela não precisa conhecer diretamente como os dados são armazenados.

Usuário → Interface
BACK-END

O que processa

A API recebe a requisição, valida os dados, aplica regras de negócio e conversa com outros serviços ou com o banco de dados.

Request → Regra → Response
BANCO DE DADOS

O que fica armazenado

Informações persistentes como usuários, produtos e pedidos podem ser armazenadas para que continuem disponíveis mesmo depois que o usuário encerra a sessão.

Dados → Persistência
QA / Visão sistêmica

Onde o QA entra nessa arquitetura?

O QA pode testar cada camada individualmente e também validar a integração entre elas. Em um e-commerce, isso significa verificar desde o comportamento da interface até a resposta da API e a persistência correta das informações.

FRONT-END Validar campos, botões, mensagens, navegação e comportamento visual da aplicação.
API Validar endpoints, métodos HTTP, Status Codes, payloads, autenticação e regras de negócio.
DATABASE Validar se os dados foram criados, alterados ou removidos corretamente quando aplicável.
INTEGRAÇÃO Garantir que o dado enviado pelo front-end seja corretamente processado pelo back-end.
E2E Validar uma jornada completa, como cadastrar usuário, escolher produto e realizar uma compra.
REGRA Verificar se o sistema respeita as regras de negócio em todos os pontos da jornada.
