Arquitetura de APIs

REST vs
GraphQL

REST e GraphQL são formas diferentes de construir e consumir APIs. Ambos permitem que aplicações troquem dados, mas organizam essa comunicação de maneiras distintas. No REST, a API normalmente expõe diferentes endpoints e métodos HTTP. No GraphQL, o cliente envia uma consulta descrevendo exatamente quais dados deseja receber.

MODELO / 01 REST

API REST recursos + HTTP

No REST, os recursos são representados por URLs ou endpoints. O cliente utiliza métodos HTTP como GET, POST, PUT, PATCH e DELETE para consultar ou modificar esses recursos.

MODELO / 02 GRAPHQL

GraphQL consulta orientada a dados

No GraphQL, normalmente existe um endpoint que recebe uma query ou mutation. O cliente informa quais campos deseja e a API retorna os dados de acordo com essa seleção.

CONCEITO / 03 CLIENT

Quem decide? servidor × cliente

A principal diferença está em como os dados são solicitados. No REST, a estrutura da resposta é geralmente definida pelo endpoint. No GraphQL, o cliente declara quais campos precisa.

A diferença na prática
API / REST

Endpoint por recurso

Para buscar um usuário, o cliente pode chamar um endpoint específico. A resposta normalmente possui uma estrutura definida pelo servidor. 

GET /usuarios/123

HTTP/1.1
Accept: application/json
VS
API / GRAPHQL

Consulta por campos

O cliente informa quais campos deseja receber através de uma query. 

query {
  usuario(id: 123) {
    nome
    email
  }
}
Exemplo / REST

Resposta de usuário

Em uma API REST, um endpoint de usuários pode retornar um objeto JSON com os dados disponíveis para aquele recurso. 

{
    "nome": "Hora do QA",
    "email": "horadoqa@test.com",
    "password": "1q2w3e4r",
    "administrador": true,
    "_id": "0v37HHrUp4Jmoyik"
}
Exemplo / GraphQL

Selecionando os campos

No GraphQL, o cliente pode solicitar somente os campos necessários para uma determinada tela. 

query {
    usuario(id: "0v37HHrUp4Jmoyik") {
        nome
        email
        administrador
    }
}
Exemplo / Response

O GraphQL devolve exatamente a estrutura solicitada

Se a query solicitar apenas nome, email e administrador, a resposta pode conter somente esses campos. Isso é uma das características que diferencia o modelo de consulta do GraphQL. 

{
  "data": {
    "usuario": {
      "nome": "Hora do QA",
      "email": "horadoqa@test.com",
      "administrador": true
    }
  }
}

Decisão / Arquitetura

Quando pensar em REST ou GraphQL?

A escolha deve considerar o tipo de aplicação, a quantidade de clientes, a complexidade dos dados e o nível de flexibilidade necessário para o consumo da API.

REST Pode ser uma boa escolha quando os recursos são bem definidos, a API possui operações HTTP claras e a estrutura das respostas é relativamente previsível.
GRAPHQL Pode ser interessante quando diferentes clientes precisam de diferentes combinações de dados ou quando existe uma necessidade maior de flexibilidade nas consultas.
QA / Visão de API

O que o QA deve testar?

REST e GraphQL possuem pontos de atenção diferentes. O QA precisa validar não apenas se a API responde, mas também se os dados, regras, erros, contratos e permissões estão funcionando corretamente.

REST / ENDPOINT Validar URL, método HTTP, parâmetros, headers, autenticação e comportamento do endpoint.
REST / STATUS Validar Status Codes como 200, 201, 400, 401, 403, 404 e 500 conforme o cenário.
GRAPHQL / QUERY Validar se queries retornam os campos solicitados e se campos inválidos são tratados corretamente.
GRAPHQL / MUTATION Validar criação, alteração e remoção de dados através das mutations disponíveis.
CONTRATO Verificar tipos, campos obrigatórios, estrutura da resposta e compatibilidade com o consumidor.
SEGURANÇA Validar autenticação, autorização, acesso indevido a dados e permissões por usuário.
