Arquitetura de APIs

GraphQL
API

GraphQL é uma linguagem de consulta para APIs que permite ao cliente declarar exatamente quais dados deseja receber. Através de um schema tipado, queries, mutations e fields, o consumidor consegue solicitar diferentes combinações de dados usando a mesma API.

CONCEITO / 01 SCHEMA

Schema tipos + campos

O schema descreve os tipos, campos e operações que a API disponibiliza para seus consumidores.

CONCEITO / 02 QUERY

Query consulta de dados

Uma query permite que o cliente informe exatamente quais campos deseja receber.

CONCEITO / 03 MUTATION

Mutation alteração de dados

Mutations representam operações que criam, alteram ou removem informações através da API.

GraphQL na prática
QUERY

Cliente escolhe os campos

A aplicação informa exatamente quais informações precisa receber. 

query {

usuario(id: 123) {
nome
email
administrador
}
}
RESPONSE

Estrutura correspondente

A resposta acompanha a estrutura solicitada pela query. 

{

"data": {
"usuario": {
"nome": "Hora do QA",
"email": "qa@test.com",
"administrador": true
}
}
}
Exemplo / Query

Selecionando campos

O cliente pode solicitar somente as informações necessárias para determinada tela. 

query {

usuario(id: "0v37HHrUp4Jmoyik") {
nome
email
administrador
}
}
Exemplo / Mutation

Alterando dados

Uma mutation representa uma operação que modifica os dados da aplicação. 

mutation {

criarUsuario(
nome: "Hora do QA",
email: "qa@test.com"
) {
id
nome
}
}
Exemplo / Response

A resposta acompanha a seleção da query

Se a query solicitar apenas nome, email e administrador, o cliente pode receber uma estrutura contendo somente esses campos solicitados. 

{

"data": {
"usuario": {
"nome": "Hora do QA",
"email": "qa@test.com",
"administrador": true
}
}
}

Decisão / Arquitetura

Quando pensar em GraphQL?

GraphQL pode ser interessante quando diferentes clientes precisam de diferentes combinações de dados ou quando existe uma necessidade maior de flexibilidade nas consultas.

MÚLTIPLOS CLIENTES Web, mobile e outros consumidores podem precisar de diferentes conjuntos de informações.
DADOS RELACIONADOS Queries podem representar relações entre diferentes tipos de dados dentro de uma mesma operação.
FLEXIBILIDADE O cliente seleciona os campos necessários para cada tela ou caso de uso.
SCHEMA Um contrato tipado permite que os consumidores conheçam os tipos e operações disponíveis.
QA / GRAPHQL API

O que o QA deve testar?

Em GraphQL, o QA precisa validar queries, mutations, schema, campos obrigatórios, tipos, erros, autenticação, autorização e regras de negócio.

QUERY Validar se a query retorna corretamente os campos solicitados.
MUTATION Validar criação, alteração e remoção de dados.
SCHEMA Validar tipos, campos, argumentos e operações disponíveis.
CAMPOS INVÁLIDOS Verificar o comportamento quando o cliente solicita campos inexistentes ou incompatíveis.
AUTENTICAÇÃO Validar tokens, credenciais, expiração e acesso sem autenticação.
AUTORIZAÇÃO Verificar se usuários podem consultar ou alterar somente os dados permitidos.
