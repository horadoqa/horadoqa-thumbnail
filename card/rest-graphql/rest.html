Arquitetura de APIs

REST
API

REST é um estilo arquitetural para construção de APIs baseado principalmente em recursos, URLs e métodos HTTP. O cliente acessa recursos através de endpoints bem definidos e utiliza operações como GET, POST, PUT, PATCH e DELETE para consultar ou modificar dados.

CONCEITO / 01 RECURSOS

Recursos representação via URL

Uma API REST organiza os dados como recursos, normalmente identificados através de URLs.

CONCEITO / 02 HTTP

Métodos HTTP ações sobre recursos

Os métodos HTTP indicam a operação desejada: GET, POST, PUT, PATCH e DELETE.

CONCEITO / 03 RESPONSE

Resposta status + dados

A API normalmente retorna um Status Code HTTP acompanhado, quando necessário, dos dados solicitados.

REST na prática
REQUEST

Buscar um usuário

O cliente utiliza GET para solicitar o recurso identificado pelo ID. 

GET /usuarios/0uxuPY0cbmQhpEz1

HTTP/1.1
Accept: application/json
RESPONSE

Dados do usuário

O servidor pode responder com Status Code 200 e o objeto solicitado. 

{
    "nome": "Hora do QA",
    "email": "horadoqa@test.com",
    "password": "1q2w3e4r",
    "administrador": "true",
    "id": 0uxuPY0cbmQhpEz1

Criar usuário

O POST normalmente é utilizado para criar um novo recurso. 

POST /usuarios

Atualizar usuário

O PUT é utilizado para atualizar um recurso existente. 

PUT /usuarios/0uxuPY0cbmQhpEz1

{
    "nome": "Hora do QA",

Fluxo / REST

Como uma requisição REST funciona

O cliente identifica o recurso que precisa acessar, escolhe o método HTTP apropriado e envia a requisição. O servidor processa a operação e devolve uma resposta.

01 / CLIENT

Requisição

O cliente envia uma requisição HTTP para a API.

02 / ENDPOINT

Recurso

A URL identifica o recurso que será acessado.

03 / METHOD

Operação

GET, POST, PUT, PATCH ou DELETE define a ação.

04 / RESPONSE

Resposta

A API devolve status HTTP e, quando necessário, os dados da operação.

Decisão / Arquitetura

Quando utilizar REST?

REST pode ser uma excelente opção quando os recursos da aplicação são bem definidos, as operações HTTP são claras e a estrutura das respostas é relativamente previsível.

RECURSOS CLAROS Quando a aplicação possui entidades bem definidas, como usuários, produtos e pedidos.
API SIMPLES Quando os consumidores conseguem trabalhar facilmente com endpoints e respostas previamente definidas.
HTTP Quando métodos, Status Codes, headers e cache HTTP fazem parte importante da arquitetura.
INTEGRAÇÕES Quando diferentes sistemas precisam consumir uma API utilizando um contrato HTTP simples e conhecido.
QA / REST API

O que o QA deve testar?

Em uma API REST, o QA deve validar o contrato, os endpoints, métodos HTTP, parâmetros, autenticação, autorização, Status Codes, payloads e regras de negócio.

ENDPOINT Validar URL, parâmetros, path variables e query parameters.
MÉTODO HTTP Verificar se GET, POST, PUT, PATCH e DELETE possuem o comportamento esperado.
STATUS CODE Validar 200, 201, 400, 401, 403, 404, 409 e 500 conforme o cenário.
PAYLOAD Validar campos obrigatórios, tipos, valores e estrutura dos JSONs enviados e recebidos.
AUTENTICAÇÃO Verificar tokens, credenciais, expiração e acesso sem autenticação.
AUTORIZAÇÃO Validar se usuários possuem acesso somente aos recursos permitidos para seu perfil.
