Testing Fundamentals

Testar é investigar.
Qualidade é o objetivo.

Existem diferentes formas de avaliar um software. Cada abordagem revela um tipo de risco, comportamento ou oportunidade de melhoria. Conhecer os tipos de testes ajuda a escolher a estratégia certa para cada cenário.

01 / Functional & Non-functional O que testar?
TEST TYPE / 01 Comportamento

Testes Funcionais

Verificam se o sistema executa as funcionalidades conforme os requisitos e as regras de negócio. Respondem à pergunta: o software faz o que deveria fazer?

Exemplo prático

Validar login, recuperação de senha, cálculo de descontos, cadastro de clientes e processamento de pagamentos.

TEST TYPE / 02 Qualidade

Testes Não Funcionais

Avaliam características como desempenho, segurança, usabilidade, acessibilidade e confiabilidade. Investigam como o sistema se comporta em diferentes condições.

Exemplo prático

Medir o tempo de resposta com muitos usuários, verificar permissões de acesso e avaliar a experiência em dispositivos móveis.

02 / Test Design Approaches Como testar?
APPROACH / 01 Black Box

Caixa Preta

Avalia entradas e saídas sem exigir conhecimento da estrutura interna ou do código-fonte. O foco está no comportamento observável do sistema.

Exemplo prático

Informar credenciais válidas e inválidas na tela de login e verificar as respostas apresentadas ao usuário.

APPROACH / 02 White Box

Caixa Branca

Examina a estrutura interna, a lógica, os caminhos de execução e as condições do código. Requer acesso ao código ou conhecimento de sua implementação.

Exemplo prático

Criar testes para verificar ramificações de uma função de cálculo, incluindo condições verdadeiras, falsas e caminhos alternativos.

APPROACH / 03 Gray Box

Caixa Cinza

Combina testes baseados no comportamento externo com conhecimento parcial da implementação, arquitetura ou estrutura dos dados.

Exemplo prático

Testar uma API conhecendo o contrato dos endpoints e o modelo de dados, verificando se as operações retornam as respostas esperadas e persistem os dados corretamente.

03 / Other Testing Types Diferentes objetivos
TEST TYPE / 04 Isolamento

Teste Unitário

Verifica uma pequena unidade do software, como uma função ou método, geralmente de forma isolada. Ajuda a identificar erros antes da integração.

Exemplo prático

Testar uma função que calcula o valor final de um pedido com descontos e impostos.

TEST TYPE / 05 Comunicação

Teste de Integração

Verifica se módulos, serviços, APIs e componentes trabalham corretamente quando se comunicam.

Exemplo prático

Confirmar se a criação de um pedido atualiza o estoque e envia corretamente os dados ao serviço de pagamento.

TEST TYPE / 06 Sistema

Teste de Sistema

Avalia o sistema integrado como um todo, verificando se seu comportamento atende aos requisitos definidos.

Exemplo prático

Realizar uma compra completa, desde a seleção dos produtos até a confirmação do pagamento.

TEST TYPE / 07 Negócio

Teste de Aceitação

Verifica se a solução atende aos critérios de aceitação e às necessidades de seus usuários e das áreas de negócio.

Exemplo prático

Validar com a área responsável se um relatório apresenta os dados e cálculos exigidos.

TEST TYPE / 08 Estabilidade

Teste de Regressão

Confirma que alterações, correções ou novas funcionalidades não prejudicaram comportamentos que já funcionavam corretamente.

Exemplo prático

Após alterar o cálculo de frete, verificar se o carrinho, os descontos e o fechamento de pedidos continuam funcionando.

TEST TYPE / 09 Investigação

Teste Exploratório

Combina aprendizado, criação de hipóteses e execução de testes para descobrir riscos e comportamentos inesperados sem depender apenas de roteiros prévios.

Exemplo prático

Explorar um formulário usando dados extremos, sequências inesperadas e mudanças rápidas de navegação.

TEST TYPE / 10 Capacidade

Teste de Desempenho

Avalia tempo de resposta, vazão, consumo de recursos, estabilidade e capacidade do sistema sob diferentes níveis de carga.

Exemplo prático

Simular milhares de requisições para medir requisições por segundo, latência e erros durante um período de carga.

TEST TYPE / 11 Proteção

Teste de Segurança

Avalia vulnerabilidades e controles de autenticação, autorização, integridade e proteção de informações.

Exemplo prático

Verificar se um usuário sem permissão consegue acessar dados ou executar operações restritas.

TEST TYPE / 12 Experiência

Teste de Usabilidade

Analisa a facilidade de uso, a compreensão das interfaces e a eficiência para concluir tarefas.

Exemplo prático

Observar se um usuário consegue concluir uma compra sem ajuda e identificar dificuldades durante a navegação.

Uma distinção importante

Funcional e não funcional classificam o objetivo ou a característica avaliada. Caixa preta, branca e cinza descrevem abordagens relacionadas ao conhecimento da estrutura interna do sistema.

As categorias se combinam

Um teste pode ser funcional e usar abordagem de caixa preta. Outro pode avaliar desempenho e utilizar conhecimento interno do sistema. A estratégia depende dos riscos, do contexto e do objetivo da avaliação.

Quality Principle / 003

Não existe um único teste capaz de garantir tudo. A qualidade nasce da combinação de diferentes perspectivas.
