Diferença conceitual

PUT vs PATCH

Os dois métodos são utilizados para alterar recursos, mas representam intenções diferentes. A principal diferença está em quanto do recurso será modificado.

MÉTODO / 01 PUT

PUT substituição

O PUT é utilizado para substituir ou atualizar a representação de um recurso. A requisição representa o estado que o recurso deve assumir após a operação.

PUT /usuarios/123

{
  "nome": "Atualizado",
  "email": "usuario@email.com",
  "password": "123456",
  "administrador": "true"
}
MÉTODO / 02 PATCH

PATCH parcial

O PATCH é utilizado para modificar parcialmente um recurso existente. A requisição descreve a alteração que deve ser aplicada ao recurso.

PATCH /usuarios/123

{
  "nome": "Atualizado"
}
COMPARAÇÃO / 03 CONCEITO

Qual a diferença? essencial

A diferença mais importante é a intenção da operação. O PUT representa a atualização da representação do recurso, enquanto o PATCH representa uma alteração parcial.

PUT
Recurso → novo estado
PATCH
Recurso → alteração parcial
DECISÃO / 04 QUANDO USAR

Quando usar PUT? full update

Use PUT quando a intenção for atualizar o recurso como um todo ou quando a API define que a operação deve receber a representação completa do recurso.

// Atualização completa
PUT /usuarios/123

{
  "nome": "João",
  "email": "joao@email.com",
  "password": "123456"
}
DECISÃO / 05 QUANDO USAR

Quando usar PATCH? partial update

Use PATCH quando você precisa alterar somente uma parte do recurso, evitando enviar campos que não fazem parte da alteração.

// Alteração parcial
PATCH /usuarios/123

{
  "nome": "João Atualizado"
}
QA / 06 TESTING

O que testar? QA

Em ambos os casos, valide o status code, os dados retornados e o estado final do recurso. No PATCH, confirme principalmente que os campos não envolvidos na alteração permaneceram intactos.

// PATCH
PATCH /usuarios/123

// Alterar somente:
"nome": "Atualizado"
RESUMO / 07 QA NOTE

Regra prática check

Pense assim: PUT define o recurso que você quer atualizar; PATCH define a mudança que você quer aplicar. A escolha também deve seguir o contrato específico da API.

PUT
Atualização da representação
PATCH
Modificação parcial
ATENÇÃO / 08 QA ALERT

Não é só sobre o JSON contrato

A diferença entre PUT e PATCH não deve ser reduzida apenas à quantidade de campos enviados. O comportamento exato depende do contrato da API. Sempre consulte a documentação para saber quais campos são obrigatórios e como cada método é implementado.
