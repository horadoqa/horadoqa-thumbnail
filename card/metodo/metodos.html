Métodos fundamentais

Métodos
HTTP

Os métodos HTTP definem a intenção de uma requisição: consultar, criar, substituir, atualizar ou remover recursos em uma aplicação. Entender cada método é fundamental para testar APIs e validar seus comportamentos.

MÉTODO / 01 READ

GET consultar

Usado para buscar ou consultar recursos. Normalmente não deve alterar o estado do servidor. Pode retornar uma lista de usuários, os detalhes de um produto ou qualquer outro recurso disponível na API.

MÉTODO / 02 CREATE

POST criar

Usado para enviar dados ao servidor, frequentemente com o objetivo de criar um novo recurso. Por exemplo, cadastrar um usuário, criar um pedido ou enviar informações para processamento.

MÉTODO / 03 REPLACE

PUT substituir

Usado para substituir a representação de um recurso. Em uma API REST, geralmente significa enviar a representação completa do recurso que deve ocupar aquela URL.

MÉTODO / 04 UPDATE

PATCH parcial

Usado para modificar parcialmente um recurso. É adequado quando apenas alguns campos precisam ser alterados, como atualizar somente o e-mail ou o status de um usuário.

MÉTODO / 05 REMOVE

DELETE remover

Usado para solicitar a remoção de um recurso. Em uma API, pode ser utilizado para excluir um usuário, cancelar um registro ou remover outro recurso identificado pela URL.

MÉTODO / 06 HEADERS

HEAD sem body

Semelhante ao GET, mas sem retornar o corpo da resposta. É útil para verificar cabeçalhos, existência de um recurso, tamanho do conteúdo ou outras informações sem precisar transferir o conteúdo completo.

MÉTODO / 07 DISCOVERY

OPTIONS opções

Usado para descobrir as opções de comunicação disponíveis para um recurso. É especialmente conhecido por aparecer em verificações de CORS realizadas por navegadores antes de determinadas requisições.

MÉTODO / 08 DEBUG

TRACE diagnóstico

Usado para diagnóstico do caminho percorrido por uma requisição. O servidor pode devolver a requisição recebida para auxiliar na identificação de problemas em determinadas configurações HTTP.
