Método HTTP

PATCH

O método PATCH é utilizado para modificar parcialmente um recurso existente. Diferente do PUT, podemos enviar somente o campo que queremos alterar.

CONCEITO / 01 PARTIAL

O que é? PATCH

O PATCH realiza uma alteração parcial em um recurso. Ele é indicado quando apenas alguns dados precisam ser modificados, sem a intenção de substituir toda a representação do recurso.

CONCEITO / 02 PUT × PATCH

Alteração parcial vs PUT

Com o PATCH, podemos enviar somente o campo que precisa ser alterado. Não é necessário reenviar nome, e-mail, senha e administrador quando queremos modificar apenas o nome.

SERVEREST / 03 ENDPOINT

Atualizar usuário API

O usuário é identificado pelo seu id na URL. Neste exemplo, vamos alterar somente o nome do usuário.

PATCH https://serverest.dev/usuarios/0uxuPY0cbmQhpEz1
REQUEST / 04 BODY

Request Body JSON

Como queremos modificar apenas o nome, o body pode conter somente o campo que será alterado.

{
  "nome": "Atualizado"
}
RESPONSE / 05 UPDATED

Resposta 200 OK

Após o processamento, a API retorna uma resposta indicando que a alteração foi realizada com sucesso.

{
  "message": "Registro alterado com sucesso"
}
QA / 06 VALIDATION

O que testar? QA

Valide se apenas o campo esperado foi alterado e se os demais dados permaneceram intactos. Depois do PATCH, utilize um GET para confirmar o resultado.

GET /usuarios/0uxuPY0cbmQhpEz1

// Esperado:
"nome": "Atualizado"
